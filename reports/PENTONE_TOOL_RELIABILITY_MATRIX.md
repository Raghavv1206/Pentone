## 1. Executive Summary

This matrix audits all **27 registered browser tools** in [`lib/tool-registry.ts`](file:///c:/project/New%20folder/Marionette/lib/tool-registry.ts).

A crucial rule of this audit: **Mocked unit tests do NOT establish physical browser reliability.**
Tools are categorized based on their verified physical execution in Chrome 156:
- **Category A (Extension Runtime Verified - PASS):** 13 tools physically exercised and passing through the live Pentone MV3 extension runtime (background service worker messaging, content script bridges, and DOM execution).
- **Category B (Extension Runtime Verified - BLOCKED):** 1 tool (`summarizePage`) physically exercised through the live extension runtime and blocked solely by on-device model availability in Chrome for Testing.
- **Category C (Automated Unit / Mock Tested Only):** 13 tools tested via unit test suites (`tests/browser-tools-integration.test.ts`, `tests/agent-execution-reasoning.test.ts`, etc.) but not yet physically verified inside the live extension browser runtime.

## 3. Prioritized Tool Defects & Fixes

1. **Defect 1 (CRITICAL — `summarizePage`):**
   - *Problem:* Attempts to call experimental `window.Summarizer` and creates an unbacked, isolated `LanguageModel` session, timing out on Chrome for Testing.
   - *Fix:* Replace the isolated session logic in `lib/ui-tools.ts` with direct delegation to Pentone's resident `LanguageModel` Prompt API session in `lib/ai.ts` using the prompt format from `useTextExplainer.ts`.
2. **Defect 2 (HIGH — `writeContent`, `translateText`, `detectLanguage`):**
   - *Problem:* Each relies on separate, unstandardized Chrome Built-in AI APIs (`window.Writer`, `window.Translator`, `window.LanguageDetector`) that fail outside specialized Canary builds.
   - *Fix:* Implement graceful fallbacks to the central Prompt API (`window.LanguageModel`) for writing and translation, and client-side regex/heuristics for language detection.
3. **Defect 3 (MEDIUM — `captureCurrentPage`):**
   - *Problem:* Does not defensively check for restricted internal URLs (`chrome://`, `about:`) prior to invoking `chrome.scripting.executeScript`.
   - *Fix:* Add the standardized restricted URL guard matching `clickElement.ts` and `findElements.ts`.
4. **Defect 4 (MEDIUM — `listen`):**
   - *Problem:* Tries to manage audio capture from the background service worker where Web Audio APIs are restricted.
   - *Fix:* Route audio capture requests to the UI context's `PersistentAudioPipeline` or `captureAudio`.
